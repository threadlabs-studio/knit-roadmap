# Contributing to the Knit tracker

Thanks for helping make Knit better. This repository is for product feedback and
tracking rather than source-code contributions.

## Before opening an issue

1. Search open and closed issues for the same behavior or request.
2. Use the bug or feature-request form so the report has enough context.
3. Remove private information before submitting anything publicly.

For questions, early ideas, and requests that still need discussion, start a
[Discussion](https://github.com/threadlabs-studio/knit-roadmap/discussions).

## Useful bug reports

Describe what you expected, what happened, how often it happens, and the smallest
set of steps that reproduces it. Browser and device families are useful. Screenshots
are welcome only after workspace content and identifying details have been removed.

Do not include authentication links, workspace URLs, document contents, email
addresses, tokens, raw logs, or account identifiers.

## What happens next

New issues begin in `status:needs-triage`. Maintainers may ask for more information,
link a duplicate, move an open-ended request to Discussions, or mark accepted work
as `status:planned`. Priority labels describe sequence, not guaranteed dates.

Implementation details may be tracked privately. A public issue will receive a
plain-language update when its externally meaningful status changes.

## Security and privacy

Do not publicly report vulnerabilities or incidents. Use
[private vulnerability reporting](https://github.com/threadlabs-studio/knit-roadmap/security/advisories/new).
See [SECURITY.md](SECURITY.md) for details.
